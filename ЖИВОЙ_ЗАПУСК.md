# Как сделать бота живым

Три отдельные задачи, не путать их между собой:

1. **GitHub** — чтобы заявка приняла ссылку и жюри увидело историю
2. **Telegram** — бот уже подключён, надо просто запустить
3. **Круглосуточно** — чтобы он не умирал, когда Хусан закрывает ноутбук

---

## 1. GitHub — 10 минут

```bash
cd suv-ai
git init
git add .
git status          # ОБЯЗАТЕЛЬНО: убедиться, что .env и *.db в списке НЕТ
git commit -m "SUV AI: движок FAO-56, спутник, Telegram-бот, экономика"
```

Если в `git status` видно `.env` — остановиться и не коммитить. Значит
`.gitignore` не подхватился. Проверить, что файл называется ровно
`.gitignore`, и повторить `git add .`

Дальше на github.com: New repository → имя `suv-ai` → **Public** → без
README (он уже есть) → Create.

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/suv-ai.git
git branch -M main
git push -u origin main
```

**Коммитить каждый день до 15 августа.** Жюри смотрит историю, и десять
дней работы выглядят иначе, чем один коммит накануне.

---

## 2. Завести настоящее поле

Регистрация через `/start` задаёт четыре вопроса и подставляет остальное
по умолчанию — суглинок, высота 500 м, без насоса. Для полей Фарруха это
неверно почти всё. Поэтому заводим из конфига:

```bash
# узнать свой chat_id: написать @userinfobot в Telegram
python scripts/seed_field.py fields/olma.json --chat ВАШ_ID
python scripts/seed_field.py fields/uzum.json --chat ВАШ_ID
```

Проверить: `/suv` в боте. Придут **два сообщения** — по саду и по
винограднику. По саду в часах работы насоса и сумах, по винограднику в
миллиметрах и без денег, потому что там самотёк.

Когда поля перейдут к Фарруху — тот же скрипт с его chat_id.

---

## 3. Запустить

Локально, для проверки:

```bash
python -m bot.main
```

Работает, пока открыт терминал. Для пилота с Фаррухом этого мало —
нужен сервер.

### Вариант А. VPS — надёжнее, ~5 долларов в месяц

Любой провайдер: Hetzner, DigitalOcean, Timeweb. Ubuntu 24.04.

```bash
ssh root@АДРЕС_СЕРВЕРА
apt update && apt install -y python3-pip git
git clone https://github.com/ВАШ_ЛОГИН/suv-ai.git
cd suv-ai && pip install -r requirements.txt --break-system-packages
nano .env          # вписать ключи ВРУЧНУЮ, их нет в репозитории
python scripts/seed_field.py fields/olma.json --chat ID_ФАРРУХА
python scripts/seed_field.py fields/uzum.json --chat ID_ФАРРУХА
```

Чтобы бот пережил разрыв ssh и перезагрузку — systemd:

```bash
cat > /etc/systemd/system/suv-ai.service <<'EOF'
[Unit]
Description=SUV AI bot
After=network-online.target

[Service]
WorkingDirectory=/root/suv-ai
ExecStart=/usr/bin/python3 -m bot.main
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now suv-ai
systemctl status suv-ai      # должно быть active (running)
journalctl -u suv-ai -f      # живой лог
```

### Вариант Б. Railway — быстрее, без ssh

railway.app → New Project → Deploy from GitHub → выбрать репозиторий.
В разделе Variables вписать `TELEGRAM_TOKEN`, `CDSE_CLIENT_ID`,
`CDSE_CLIENT_SECRET`. Start command: `python -m bot.main`

Быстрее поднять, но файловая система эфемерная: база `suv.db` сотрётся
при передеплое вместе со всеми записями пилота. Для девяти дней сойдёт,
если не передеплоивать. **Для данных, на которых строится KPI, лучше VPS.**

## Ежедневный ритм пилота

Каждый день, пока идёт пилот:

1. Фаррух получает `/suv` (или отправляет сам)
2. Полил — пишет `/bajardim 9`, где 9 — часы работы насоса
3. Не полил — ничего не пишет, это тоже данные

Через неделю:

```bash
sqlite3 suv.db "SELECT r.generated_on, r.field_id, r.action_day, r.gross_m3,
  a.followed, a.actual_m3, a.note FROM recommendations r
  LEFT JOIN actions a ON a.recommendation_id=r.id ORDER BY r.generated_on;"
```

Это и есть слайд с результатами пилота. Единственный, который нельзя
получить кодом.

---

## Безопасность

- `.env` не коммитить никогда
- Токен и секрет не показывать на скриншотах
- Если засветились — удалить и создать заново, это минута

Утёкший `TELEGRAM_TOKEN` означает, что писать Фарруху от имени вашего
бота сможет кто угодно.
