# ЗАПУСК — подключение живых данных

Пошагово. Всё бесплатно, ключи выдают сразу. Считайте на 40–60 минут
на всё, если ничего не сломается.

---

## Шаг 0. Поставить и убедиться, что движок жив

```bash
cd suv-ai
pip install -r requirements.txt
python -m pytest tests/ -q
```

Должно быть `31 passed`. Если да — расчётная часть в порядке и интернет ей
не нужен. Дальше подключаем внешние источники.

```bash
python scripts/check_live.py
```

Сейчас покажет: движок ОК, погода ОК, спутник и Telegram — ПРОПУСК.
Задача следующих шагов — сделать все четыре строки зелёными.

## Шаг 1. Погода — ничего делать не нужно

Open-Meteo работает без регистрации и без ключа. Если в `check_live.py`
строка «Погода» уже ОК — этот шаг пройден.

Если СБОЙ — проблема в интернете или провайдер режет `api.open-meteo.com`.
Проверьте через телефон в режиме модема.

## Шаг 1.5. Куда класть ключи

Все ключи живут в файле **`.env` в корне проекта** — рядом с `README.md`,
не внутри `scripts/` и не внутри `suv/`.

```
CDSE_CLIENT_ID=sh-...
CDSE_CLIENT_SECRET=...
TELEGRAM_TOKEN=...
```

Без пробелов вокруг `=`, без кавычек, каждая переменная с новой строки.

Проверить, что файл читается:

```bash
python scripts/check_live.py
```

Вторая строка вывода покажет `Ключи из .env: ...` со списком того, что
реально прочиталось. Если написано `.env не прочитан` — файл лежит не там
или называется не так.

**Windows, частая ловушка.** Проводник по умолчанию скрывает расширения,
и Блокнот сохраняет файл как `.env.txt`. Проверьте: в Проводнике
View → Show → File name extensions. Файл должен называться ровно `.env`,
без `.txt`.

Команда `export` — это Linux и macOS. **В PowerShell она не работает.**
Если хочется задать переменную на одну сессию, там синтаксис другой:

```powershell
$env:CDSE_CLIENT_ID = "sh-..."
```

Но проще положить всё в `.env` и не думать об этом.

`.env` уже в `.gitignore` и в репозиторий не попадёт. **Никогда не
показывайте содержимое `.env` на скриншотах** — секрет из скриншота
считается утёкшим, его нужно удалять и создавать заново.

## Шаг 2. Telegram-бот — 3 минуты

1. Открыть в Telegram **@BotFather**
2. Отправить `/newbot`
3. Ввести название: `SUV AI`
4. Ввести username — обязан заканчиваться на `bot`, например `suvai_pilot_bot`
5. BotFather пришлёт токен вида `8123456789:AAF-xxxxxxxxxxxxxxxxxxxxx`

```bash
export TELEGRAM_TOKEN='8123456789:AAF-xxxxxxxxxxxxxxxxxxxxx'
python scripts/check_live.py
```

Строка Telegram должна стать ОК и показать имя бота.

**Не кладите токен в git.** Если он утечёт в публичный репозиторий, любой
сможет писать от имени вашего бота. Токен живёт только в переменной
окружения или в `.env`, который уже в `.gitignore`.

## Шаг 3. Спутник Copernicus — 10 минут

1. `dataspace.copernicus.eu` → **Sign in** → **Register** (почта + пароль)
2. Подтвердить почту
3. Войти → меню профиля в правом верхнем углу → **Sentinel Hub**
4. Раздел **OAuth clients** → **Create** (имя любое, например `suv-ai`)
5. Скопировать **Client ID** и **Client Secret**

**Секрет показывают ровно один раз.** Не закроете вкладку — не потеряете.

```bash
export CDSE_CLIENT_ID='...'
export CDSE_CLIENT_SECRET='...'
pip install rasterio
python scripts/check_live.py
```

Возможные ответы по строке «Снимок NDVI»:

- `NDVI = 0.72, чистых пикселей 95%` — идеально
- `все снимки закрыты облаками` — **это не ошибка.** Движок в таком случае
  честно переключается на календарь культуры. Попробуйте через пару дней.
- `авторизация` — почти всегда неверный Client Secret или OAuth-клиент
  создан не в разделе Sentinel Hub

## Шаг 4. Поле брата — самое важное

Скопируйте шаблон и заполните **реальными** данными:

```bash
cp scripts/field.example.json field.json
```

Что спросить у брата — эти семь вопросов и есть весь онбординг:

| Поле в json | Вопрос брату |
|---|---|
| `lat` / `lon` | Пусть встанет посреди поля и пришлёт геолокацию в Telegram |
| `hectares` | Сколько гектаров |
| `crop` | `cotton`, `winter_wheat`, `onion`, `tomato`, `apple`, `grape` |
| `planting_date` | Когда сеяли, в формате `2026-04-15` |
| `soil` | `sandy_loam`, `loam`, `silt_loam`, `clay_loam`, `clay` |
| `water_table_depth_m` | **На какой глубине грунтовые воды** |
| `irrigation_method` | `furrow` (по бороздам), `sprinkler`, `drip` |
| `last_irrigation_date` | **Когда поливал в последний раз** |
| `baseline_m3_per_ha` | Сколько кубов за один полив, и сколько поливов за сезон |

Два из них решают всё:

**`water_table_depth_m`** — если не знает точно, пусть спросит в районном
водхозе или посмотрит на глубину воды в ближайшем коллекторе. Именно из-за
этого параметра первая версия движка ошибалась почти вдвое. Для Самарканда
типично 3–4 м, для Ферганы 1,5–2,5 м.

**`last_irrigation_date`** — без неё система считает, что поле сегодня
полное, и скажет «поливать не надо» посреди засухи. Худшее первое
впечатление для фермера.

**`baseline_m3_per_ha`** — база сравнения. Без неё нет цифры экономии.
Спрашивайте не «сколько примерно», а «сколько раз поливал в прошлом году
и по сколько часов подавал воду». Часы × расход канала = кубы.

Затем:

```bash
python scripts/run_field.py field.json
```

Получите готовое сообщение на узбекском, расчёт по дням и сравнение с его
старым графиком.

## Шаг 5. Запустить бота

```bash
python -m bot.main
```

Найдите бота по username в Telegram, отправьте `/start`, пройдите
регистрацию (4 вопроса), затем `/suv`.

Команды:
- `/suv` — получить рекомендацию
- `/bajardim` — «я полил», записывает выполнение
- `/tejaldi` — сколько сэкономлено с начала сезона

`/bajardim` важнее, чем кажется: без него у вас есть только то, что система
советовала, но нет того, что фермер сделал. А KPI конкурса — про
подтверждённый результат, не про совет.

## Что записывать всю неделю

Заведите обычную таблицу. Каждая строка — один день:

| Дата | Что сказала система | Что сделал брат | Сколько подал воды | Комментарий брата |
|---|---|---|---|---|

Эта таблица — ваш слайд с результатами пилота. Он сейчас пустой, и это
единственное, чего не хватает заявке.

Отдельно: **если брат скажет, что рекомендация неверная — запишите это
дословно.** Расхождение, которое вы сами нашли и объяснили, на питче
работает лучше, чем идеальные цифры. Так уже было с грунтовыми водами.
