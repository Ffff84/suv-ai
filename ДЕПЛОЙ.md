# Деплой: VPS + автовыкатка с GitHub

Бот крошечный: Python, SQLite, исходящие запросы. Хватит самого дешёвого
тарифа — 1 vCPU, 1 ГБ памяти, Ubuntu 24.04. Никаких входящих портов,
кроме SSH, боту не нужно.

---

## 2. Покупка (Hetzner)

1. **Регистрация:** accounts.hetzner.com → Sign up. Подтвердить почту.
   Могут попросить фото паспорта — это нормально, отвечают за часы.
2. **Оплата:** привязать карту или PayPal.
3. **SSH-ключ** (на своём компьютере, PowerShell):
   ```
   ssh-keygen -t ed25519
   ```
   Enter на все вопросы. Публичный ключ — файл
   `C:\Users\<вы>\.ssh\id_ed25519.pub`, его содержимое скопировать.
4. **Сервер:** console.hetzner.cloud → New project `suv-ai` → Add Server:
   - Location: Falkenstein или Helsinki (любой)
   - Image: **Ubuntu 24.04**
   - Type: Shared vCPU → **CX22** (x86) — самый дешёвый достаточный
   - SSH keys: Add SSH key → вставить скопированный `.pub`
   - Create & Buy now
5. Записать **IP-адрес** сервера из панели.

Проверка с компьютера:

```
ssh root@ВАШ_IP
```

Если открылась консоль сервера — куплено правильно.

## 3. Первичная настройка сервера

Один раз, руками, по SSH:

```bash
apt update && apt install -y python3-pip git
git clone https://github.com/Ffff84/suv-ai.git /root/suv-ai
cd /root/suv-ai
pip install -r requirements.txt --break-system-packages

nano .env      # вписать ВРУЧНУЮ — этих ключей нет и не должно быть в git
```

Содержимое `.env` на сервере:

```
TELEGRAM_TOKEN=НОВЫЙ_токен_после_перевыпуска_у_BotFather
CDSE_CLIENT_ID=...
CDSE_CLIENT_SECRET=...
ALLOWED_CHAT_IDS=43348525,1724124721
OBSERVER_CHAT_IDS=1724124721
```

Завести поля и службу:

```bash
python3 scripts/seed_field.py fields/olma.json --chat 43348525
python3 scripts/seed_field.py fields/uzum.json --chat 43348525

cat > /etc/systemd/system/suv-ai.service <<'EOF'
[Unit]
Description=SUV AI bot
After=network-online.target

[Service]
WorkingDirectory=/root/suv-ai
ExecStart=/usr/bin/python3 -m bot.main
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now suv-ai
systemctl status suv-ai        # должно быть active (running)
```

**Важно:** Telegram разрешает только ОДНО long-polling-подключение на
токен. Как только бот заработал на сервере — остановить локальный на
ноутбуке, иначе они будут отбирать сообщения друг у друга.

Минимальная гигиена:

```bash
ufw allow OpenSSH && ufw enable
```

## 4. Пайплайн: push в GitHub → автоматически на сервер

Схема: GitHub Actions при каждом push в `main` сначала гоняет тесты,
затем по SSH заходит на сервер, забирает свежий код и перезапускает
службу. Файл workflow уже лежит в репозитории:
`.github/workflows/deploy.yml`. Он «спит», пока не заданы секреты.

### Настройка (один раз)

1. **Отдельный ключ для деплоя** (на своём компьютере):
   ```
   ssh-keygen -t ed25519 -f deploy_key -N '""'
   ```
   Появятся два файла: `deploy_key` (секретный) и `deploy_key.pub`.

2. **Пустить этот ключ на сервер:**
   ```bash
   # на сервере:
   echo 'СОДЕРЖИМОЕ_deploy_key.pub' >> /root/.ssh/authorized_keys
   ```

3. **Секреты в GitHub:** репозиторий → Settings → Secrets and variables →
   Actions → New repository secret, три штуки:
   - `VPS_HOST` — IP сервера
   - `VPS_USER` — `root`
   - `VPS_SSH_KEY` — содержимое файла `deploy_key` (секретного, не .pub),
     целиком, включая строки BEGIN/END

4. Файл `deploy_key` после этого с компьютера удалить — он больше нигде
   не нужен.

### Как это работает дальше

Каждый `git push origin main`:

1. GitHub Actions запускает `pytest` — сломанный код на сервер не уедет;
2. при зелёных тестах заходит на сервер по SSH;
3. `git reset --hard origin/main` — код обновлён. `.env` и `suv.db` не
   тронуты: они не в git, а reset не трогает неотслеживаемые файлы;
4. `pip install -r requirements.txt` — на случай новых зависимостей;
5. `systemctl restart suv-ai` — бот перезапущен с новым кодом.

От push до работающего обновления — около минуты. Смотреть за процессом:
вкладка **Actions** на GitHub; живой лог бота на сервере:
`journalctl -u suv-ai -f`.

### Проверка пайплайна

Поменять любую строчку (например, в README), закоммитить, запушить.
Через минуту-две во вкладке Actions должны быть две зелёные галочки,
а `systemctl status suv-ai` на сервере — показывать свежий перезапуск.
