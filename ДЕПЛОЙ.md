# Деплой: VPS + автовыкатка с GitHub

Бот крошечный: Python, SQLite, исходящие запросы. Хватит самого дешёвого
тарифа — 1 vCPU, 1 ГБ памяти, Ubuntu 24.04. Никаких входящих портов,
кроме SSH, боту не нужно.

## 2. Покупка (Hetzner)

1. **Регистрация:** accounts.hetzner.com → Sign up. Подтвердить почту.
   Могут попросить фото паспорта — это нормально, отвечают за часы.
2. **Оплата:** привязать карту или PayPal.
3. **SSH-ключ** (на своём компьютере, PowerShell):
   ```
   ssh-keygen -t ed25519
   ```
   Enter на все вопросы. Публичный ключ — файл
   `C:\Users\<вы>\.ssh\id_ed25519.pub`, его содержимое скопировать.
4. **Сервер:** console.hetzner.cloud → New project `suv-ai` → Add Server:
   - Location: Falkenstein или Helsinki (любой)
   - Image: **Ubuntu 24.04**
   - Type: Shared vCPU → **CX22** (x86) — самый дешёвый достаточный
   - SSH keys: Add SSH key → вставить скопированный `.pub`
   - Create & Buy now
5. Записать **IP-адрес** сервера из панели.

Проверка с компьютера:

```
ssh root@ВАШ_IP
```

Если открылась консоль сервера — куплено правильно.

## 3. Первичная настройка сервера

**Быстрый путь.** Зайти на сервер (`ssh root@ВАШ_IP`) и выполнить одну
строку — она сделает всё из этого раздела:

```bash
curl -fsSL https://raw.githubusercontent.com/Ffff84/suv-ai/main/scripts/setup_server.sh | FARMER_CHAT_ID=ВАШ_CHAT_ID bash
```

`FARMER_CHAT_ID` — Telegram chat_id фермера (узнать: написать боту
@userinfobot). Без него скрипт тоже отработает, но поля к чату не привяжет.

Скрипт поставит пакеты, склонирует код, создаст шаблон `.env`, заведёт
поля и службу systemd. Останется вписать ключи в `/root/suv-ai/.env`
(их не знает никто, кроме вас) и выполнить `systemctl start suv-ai`.
Повторный запуск безопасен: `.env` не перезаписывается.

Ниже — то же самое вручную, шаг за шагом.

Один раз, руками, по SSH:

```bash
apt update && apt install -y python3-pip git
git clone https://github.com/Ffff84/suv-ai.git /root/suv-ai
cd /root/suv-ai
pip install -r requirements.txt --break-system-packages

nano .env      # вписать ВРУЧНУЮ — этих ключей нет и не должно быть в git
```

Содержимое `.env` на сервере:

```
TELEGRAM_TOKEN=НОВЫЙ_токен_после_перевыпуска_у_BotFather
CDSE_CLIENT_ID=...
CDSE_CLIENT_SECRET=...
ALLOWED_CHAT_IDS=CHAT_ID_ФЕРМЕРА,CHAT_ID_НАБЛЮДАТЕЛЯ
OBSERVER_CHAT_IDS=CHAT_ID_НАБЛЮДАТЕЛЯ
FIELD_STATUS_CHAT_IDS=
MINIAPP_URL=
```

`FIELD_STATUS_CHAT_IDS` — закрытое демо экрана «🌾 Dala holati». Пусто =
экрана нет ни у кого и бот ведёт себя ровно как до этой ветки; вписать
свой chat_id — кнопка появится только в этом чате. Так новая функция
обкатывается на живом сервере, не доходя до фермера.

`MINIAPP_URL` — необязательный. Пусто: фермер обводит поле, обходя углы и
отправляя геолокацию с каждого. Это работает всегда и ничего не требует.
Заполнить — появится ещё и кнопка «🗺 Xaritada chizish»: карта, на которой
поле обводится пальцем, не выходя из дома (см. раздел «Mini App» ниже).

Завести поля и службу:

```bash
python3 scripts/seed_field.py fields/olma.json --chat CHAT_ID_ФЕРМЕРА
python3 scripts/seed_field.py fields/uzum.json --chat CHAT_ID_ФЕРМЕРА

cat > /etc/systemd/system/suv-ai.service <<'EOF'
[Unit]
Description=SUV AI bot
After=network-online.target

[Service]
WorkingDirectory=/root/suv-ai
ExecStart=/usr/bin/python3 -m bot.main
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now suv-ai
systemctl status suv-ai        # должно быть active (running)
```

**Важно:** Telegram разрешает только ОДНО long-polling-подключение на
токен. Как только бот заработал на сервере — остановить локальный на
ноутбуке, иначе они будут отбирать сообщения друг у друга.

Минимальная гигиена:

```bash
ufw allow OpenSSH && ufw enable
```

## 4. Пайплайн: push в GitHub → автоматически на сервер

Схема: GitHub Actions при каждом push в `main` сначала гоняет тесты,
затем по SSH заходит на сервер, забирает свежий код и перезапускает
службу. Файл workflow уже лежит в репозитории:
`.github/workflows/deploy.yml`. Он «спит», пока не заданы секреты.

### Настройка (один раз)

1. **Отдельный ключ для деплоя** (на своём компьютере):
   ```
   ssh-keygen -t ed25519 -f deploy_key -N '""'
   ```
   Появятся два файла: `deploy_key` (секретный) и `deploy_key.pub`.

2. **Пустить этот ключ на сервер:**
   ```bash
   # на сервере:
   echo 'СОДЕРЖИМОЕ_deploy_key.pub' >> /root/.ssh/authorized_keys
   ```

3. **Секреты в GitHub:** репозиторий → Settings → Secrets and variables →
   Actions → New repository secret, три штуки:
   - `VPS_HOST` — IP сервера
   - `VPS_USER` — `root`
   - `VPS_SSH_KEY` — содержимое файла `deploy_key` (секретного, не .pub),
     целиком, включая строки BEGIN/END

4. Файл `deploy_key` после этого с компьютера удалить — он больше нигде
   не нужен.

### Как это работает дальше

Каждый `git push origin main`:

1. GitHub Actions запускает `pytest` — сломанный код на сервер не уедет;
2. при зелёных тестах заходит на сервер по SSH;
3. `git reset --hard origin/main` — код обновлён. `.env` и `suv.db` не
   тронуты: они не в git, а reset не трогает неотслеживаемые файлы;
4. `pip install -r requirements.txt` — на случай новых зависимостей;
5. `systemctl restart suv-ai` — бот перезапущен с новым кодом.

От push до работающего обновления — около минуты. Смотреть за процессом:
вкладка **Actions** на GitHub; живой лог бота на сервере:
`journalctl -u suv-ai -f`.

### Если что-то пошло не так

**`telegram.error.Conflict: terminated by other getUpdates request`**
в `journalctl -u suv-ai` — на один токен работают два бота сразу. Почти
всегда это забытый локальный запуск на ноутбуке. Telegram разрешает
только одно long-polling-подключение: пока живы оба, они отбирают
сообщения друг у друга, и фермер видит случайные пропуски. Остановите
локальный (в его терминале Ctrl+C, либо `taskkill /IM python.exe /F` в
Windows) — служба на сервере поднимется сама через `RestartSec=10`.

**Деплой падает с «На сервере нет /root/suv-ai»** — первичная настройка
не сделана, вернитесь к разделу 3.

**«Сервер не пустил по ключу» (Permission denied)** — в
`~/.ssh/authorized_keys` на сервере нет публичной части деплой-ключа,
либо `VPS_USER` указывает на другого пользователя.

**«VPS_SSH_KEY не читается как приватный ключ»** — в секрет попал
`deploy_key.pub` вместо `deploy_key`, или ключ скопирован без строк
BEGIN/END.

### Проверка пайплайна

Поменять любую строчку (например, в README), закоммитить, запушить.
Через минуту-две во вкладке Actions должны быть две зелёные галочки,
а `systemctl status suv-ai` на сервере — показывать свежий перезапуск.

## 5. Ключи Copernicus (если понадобится пересоздать)

Погода (Open-Meteo) ключа не требует. Спутник — требует, и без него бот
работает, просто считает по календарю культуры.

1. `dataspace.copernicus.eu` → Sign in → Register, подтвердить почту
2. Войти → меню профиля справа вверху → **Sentinel Hub**
3. Раздел **OAuth clients** → **Create**, имя любое (например `suv-ai`)
4. Скопировать **Client ID** и **Client Secret** в `.env`

**Секрет показывают ровно один раз** — не закрывайте вкладку, пока не
сохранили.

Проверка: `python scripts/check_live.py`. По строке «Снимок NDVI»:

- `NDVI = 0.72, чистых пикселей 95%` — всё работает
- `все снимки закрыты облаками` — **не ошибка**: движок честно
  переключается на календарь культуры, попробуйте через пару дней
- ошибка авторизации — почти всегда неверный Client Secret либо
  OAuth-клиент создан не в разделе Sentinel Hub

## 6. Ритм пилота

Каждый день, пока идёт пилот:

1. Фермер получает рекомендацию (или запрашивает кнопкой «💧 Suv holati»)
2. Полил — отмечает кнопкой «✅ Suv berdim» и указывает часы работы насоса
3. Не полил — не отмечает ничего; отсутствие отметки это тоже данные

Выгрузить накопленное с сервера:

```bash
sqlite3 /root/suv-ai/suv.db "SELECT r.generated_on, r.field_id, r.action_day,
  r.gross_m3, a.followed, a.actual_m3, a.note FROM recommendations r
  LEFT JOIN actions a ON a.recommendation_id=r.id ORDER BY r.generated_on;"
```

Это и есть результаты пилота — единственная таблица, которую нельзя
получить кодом: её наполняет фермер.

## 7. Mini App: обводка поля пальцем (необязательно)

Контур поля нужен всему, что опирается на границы: снимок NDVI ровно по
полю вместо квадрата вокруг точки, равномерность полива, фото со
спутника. Собрать его можно двумя путями.

**Путь без домена — работает сразу.** Фермер открывает «🌾 Dala holati»,
жмёт «🗺 Dalani chizish», обходит поле по углам и с каждого отправляет
геолокацию. Бот считает площадь и переспрашивает: «Dalangiz 3,0 gektar
chiqdi. To'g'rimi?». Настраивать нечего.

**Путь с картой — через домен проекта.** Telegram не откроет веб-вид по
http, самоподписанный сертификат тоже не примет. Но `suv-ai.online` уже
указывает на тот же сервер, где стоит бот, и лендинг раздаётся из
`/var/www/suv-ai/` — той самой папки, куда деплой кладёт страницу
обводки. Поэтому настраивать nginx не нужно вообще: файл оказывается
доступен по адресу лендинга сам собой.

Один раз создать папку и положить страницу:

```bash
mkdir -p /var/www/suv-ai && cp /root/suv-ai/miniapp/draw.html /var/www/suv-ai/draw.html
```

Проверить, что отдаётся (ждём 200, а не 404):

```bash
curl -sI https://suv-ai.online/draw.html | head -1
```

Прописать адрес боту и перезапустить:

```bash
echo "MINIAPP_URL=https://suv-ai.online/draw.html" >> /root/suv-ai/.env
systemctl restart suv-ai
```

После этого в режиме обводки появится кнопка «🗺 Xaritada chizish».

Копировать `draw.html` руками при каждом обновлении не нужно: деплой
делает это сам, раз папка существует.

**Команды набирать на сервере, а не в Windows.** В cmd.exe одинарные
кавычки не кавычки, а `2>/dev/null` он перехватывает как своё
перенаправление — однострочник `ssh root@... '...'` до сервера доезжает
обрывком. Проще зайти по `ssh root@ВАШ_IP` и работать в тамошнем bash.

**Как обводить поле правильно.** Углы надо отмечать **подряд, обходя поле
по периметру** — как идёте, такой контур и получится. Это не придирка:
бот берёт присланный порядок как есть и намеренно не «исправляет» его.

ТЗ предлагало сортировать углы по азимуту от центра, чтобы сбитый
порядок сам собой развязывался. Так делать нельзя. Для Г-образного
участка вдоль канала (600×60 м плюс отвод 60×340 м, настоящие 5,6 га)
такая сортировка съедает вырез и уверенно сообщает **13,6 гектара** —
завышение в два с половиной раза. Поймать подмену нечем: контур,
собранный по возрастанию угла, самопересекающимся не бывает никогда,
так что проверка на «узел» его пропускает.

Поэтому правило такое:

- порядок обхода принимается как есть — для любой формы поля;
- развернуть углы бот берётся только когда ответ единственный: если все
  углы лежат на выпуклой оболочке, простой контур через них ровно один,
  и это уже не догадка, а вычисление;
- во всех остальных случаях бот отвечает «Burchaklar tartibi tushunarsiz
  bo'ldi» и просит обойти поле заново, а не выдумывает площадь.

Прямоугольное или трапециевидное поле восстановится при любом порядке
углов. Г-образное — только при обходе по периметру.
